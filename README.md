# Markdown-Editor

一个开箱即用的在线 Markdown 编辑 / 预览工具，专注于**微信公众号排版场景**：分屏实时预览、富文本一键复制、外链转脚注、水印、模板套用。

纯静态三文件，无需安装依赖、无需构建，起个本地服务就能用。

## 特性

**编辑与渲染**

- 左右分屏实时预览，中间分隔条可拖拽调整比例
- 双向同步滚动（可关闭）
- 代码块语法高亮（highlight.js）
- 数学公式渲染（KaTeX，行内 `$...$` / 块级 `$$...$$`）
- Mermaid 图表（流程图、时序图、类图等）
- 支持 `marked` 的 GFM 语法：表格、任务列表、删除线等
- 底部实时统计字符数 / 词数 / 行数

**微信排版**

- 一键复制为富文本，可直接粘贴进公众号编辑器（保留代码高亮与主题样式）
- 外链转脚注：把正文中的 `http(s)` 链接变成上标序号，并在文末生成「参考文献」区块
- 水印：可自定义文字、颜色、字号、透明度、角度、间距，同步作用于预览与复制结果
- 模板：用 `{{ content }}` 占位符预置头尾结构，一键套用

**效率工具**

- 文档大纲：右侧悬浮面板，点击标题左（源码）右（预览）双栏联动跳转
- 全屏预览 + 页宽调节（窄 680 / 中 880 / 宽 1100 / 超宽 1400 / 铺满）
- 标题自动编号（H1–H3）
- 一键插入目录（TOC）
- 方格背景（便于截图对齐）
- 打开本地 `.md` / `.markdown` / `.txt` / `.mdx` 文件
- URL 链接采集：输入网址抓取正文并转为 Markdown
- 更多工具导航：内置同类在线工具与开源项目的快捷入口
- 4 套主题（GitHub / 山吹 / 山月 / 凝夜紫），默认 GitHub

**持久化**

- 编辑内容自动存入 localStorage，刷新不丢

## 快速开始

### 方式一：本地 HTTP 服务（推荐）

```bash
cd mdtu-editor

# Python 3
python -m http.server 20001

# 或 Node
npx serve . -l 20001
```

浏览器打开 <http://localhost:20001>。

> 端口遵循 `200xx` 约定；若 `20001` 被占用，依次顺延为 `20002`、`20003`……

### 方式二：直接双击打开

直接双击 `index.html` 以 `file://` 方式打开也可以运行。但部分浏览器对 `file://` 页面的 localStorage 有限制，可能出现内容无法保存的情况，**建议优先使用本地服务**。

### 环境要求

- 任意现代浏览器（Chrome / Edge / Firefox / Safari）
- **需要联网**：marked、highlight.js、KaTeX、Mermaid、DOMPurify 均通过 jsDelivr CDN 加载

## 使用说明

### 编辑与预览

左侧写 Markdown，右侧实时渲染。顶部工具栏提供 18 个语法插入按钮：

| 分组 | 按钮 |
|------|------|
| 文本 | 粗体、斜体、删除线 |
| 标题 | H1、H2、H3 |
| 插入 | 链接、图片、行内代码、代码块 |
| 列表 | 无序列表、有序列表、任务列表、引用 |
| 块级 | 分割线、表格、数学公式、Mermaid 图表 |
| 右侧 | URL 链接采集、清空内容 |

### 复制到公众号

点击右上角**「复制」**按钮，渲染结果会以富文本形式写入剪贴板，直接粘贴到公众号编辑器即可，样式与代码高亮一并保留。

底层使用 `document.execCommand('copy')` 配合 Range 选区实现——这是个已废弃但兼容性最好的 API，目前是浏览器里复制富文本最稳的方案。

### 外链转脚注

点击顶部**「外链转脚注」**开启（按钮高亮为激活态）。

原文：

```markdown
更多信息参考 [Google](https://google.com) 和 [MDN](https://developer.mozilla.org)
```

渲染结果：

> 更多信息参考 Google<sup>[1]</sup> 和 MDN<sup>[2]</sup>
>
> ---
> **参考文献**
> [1] https://google.com
> [2] https://developer.mozilla.org

用于绕开公众号正文不支持外链跳转的限制。

### 水印

点击顶部**「水印」**按钮打开设置面板，左侧调参、右侧实时预览。

| 参数 | 范围 | 默认 |
|------|------|------|
| 水印文字 | 任意文本 | 空（附 3 个快捷预设） |
| 颜色 | 取色器 | `#999999` |
| 字号 | 10–48 px | 16 px |
| 不透明度 | 3%–60% | 12% |
| 旋转角度 | -90°–90° | -30° |
| 排列间距 | 80–360 px | 180 px |
| 复制时带上水印 | 开关 | 开 |

实现上有意做了两套渲染路径：

- **预览**：生成 SVG data URI 作为平铺背景，性能好、不污染 DOM
- **复制**：公众号编辑器会过滤 SVG data URI 背景，因此改为生成一组绝对定位的 `<span>` 节点铺在正文上，DOM 元素更容易在粘贴后存活

水印只作用于预览和复制结果，**不会改动 Markdown 源码**。

### 模板

核心是 `{{ content }}` 占位符——它代表你当前的正文。

1. 点击**「使用模板」**打开模板管理
2. 新建模板，填写名称与内容，用 `{{ content }}` 标记正文插入位置
3. 保存后选中该模板，点击**「应用模板」**

示例模板：

```markdown
# 技术周报

> 作者：XXX ｜ 发布日期：XXX

{{ content }}

---

> 关注我的公众号 👇
```

应用后，编辑器里的原有正文会被塞进 `{{ content }}` 的位置，上下自动拼接头尾。模板保存在 localStorage。

### 文档大纲

点击顶部**「大纲」**按钮，面板在右侧垂直居中悬浮。

- 自动扫描 H1–H6，按层级缩进展示
- 点击条目时，编辑器与预览区**同时**平滑滚动到对应位置
- 滚动预览区时自动高亮当前标题
- 内容编辑后实时更新
- 再次点击「大纲」或点 `×` 关闭

### 全屏与页宽

点击预览区右上角全屏图标进入全屏（`Esc` 退出）。全屏时工具栏左侧出现**页宽**控件：

窄 680 / 中 880 / 宽 1100 / 超宽 1400 / 全屏宽

切换为正中的「纸张」样式（白底 + 阴影 + 圆角）。选择会记入 localStorage，下次进入全屏自动沿用。

### 打开本地文件

点击顶部**「打开」**选择本地文件，支持 `.md` / `.markdown` / `.txt` / `.mdx`，以 UTF-8 读入。若编辑器已有内容会先弹确认，避免误覆盖。

注意：这只是一个**读取**动作，页面内的编辑不会写回原文件。

## 技术栈

| 库 | 版本 | 用途 |
|----|------|------|
| [marked](https://github.com/markedjs/marked) | 4.3.0 | Markdown 解析 |
| [highlight.js](https://github.com/highlightjs/highlight.js) | 11.9.0 | 代码语法高亮 |
| [KaTeX](https://github.com/KaTeX/KaTeX) | 0.16.9 | 数学公式渲染 |
| [Mermaid](https://github.com/mermaid-js/mermaid) | 10.9.0 | 图表渲染 |
| [DOMPurify](https://github.com/cure53/DOMPurify) | 3.1.6 | HTML 消毒，防 XSS |

> ⚠️ **版本注意**：marked 固定在 **v4**。v12 的 renderer API（如 `renderer.link` 签名）与 v4 不兼容，升级会导致外链转脚注等功能失效，改动前请先确认 API 差异。

## 已知限制

1. **没有导出功能**——不支持导出 `.md` / `.html` / PDF。内容只在 localStorage 里，需要留存请自行复制备份。
2. **「打开」是只读的**——读取文件后，页面内的编辑不会写回磁盘。
3. **URL 采集依赖公共代理**——走 `api.allorigins.win` 做 CORS 转发，该服务不稳定时此功能会失败，且部分站点会因反爬而抓取不全。
4. **离线不可用**——依赖库全部走 CDN，无网络时渲染链路会瘫痪。
5. **水印不保证在公众号生效**——已用 DOM 节点方案提高存活率，但微信仍可能二次过滤样式，粘贴后请确认。
6. **主题切换入口默认隐藏**——见下方 FAQ。
7. **无移动端适配**——分屏布局面向桌面端设计。

## FAQ

**内容会丢吗？**

换浏览器、清缓存、使用无痕模式都会导致 localStorage 数据丢失。`Ctrl+S` 也只是写 localStorage，不等于存盘。重要内容请手动复制出来备份。

**怎么重新显示主题切换下拉框？**

主题选择器在 `index.html` 中被隐藏了（默认锁定 GitHub 主题）。找到第 39 行左右的这两处，删掉 `style="display:none;"` 即可：

```html
<div class="toolbar-group" style="display:none;">   <!-- 主题 select 外层 -->
<div class="toolbar-divider" style="display:none;"></div>
```

**改了默认文档为什么没生效？**

默认内容只在 localStorage 中没有 `mdtu-content` 时加载。老用户需要在控制台执行：

```js
localStorage.removeItem('mdtu-content')
```

再刷新页面。

**渲染卡住了 / 一片空白？**

先确认能访问 `cdn.jsdelivr.net`，依赖加载失败会导致整条渲染链路不可用。

## 未来功能升级

详细的规划背景、调研结论与技术方案见 **[ROADMAP.md](./ROADMAP.md)**。这里是清单式摘要：

| 编号 | 模块 | 优先级 | 状态 | 说明 |
|------|------|--------|------|------|
| **F1** | 导出能力 | P0 | ⬜ 待规划 | 顶部新增「导出」下拉：复制 MD / 导出 PDF / 导出 Word / 导出 HTML，全部走浏览器下载 |
| **F2** | 界面与交互优化 | P1 | ⬜ 待规划 | 字体与排版、交互效率、提示反馈、无障碍与键盘、响应式五个方向 |
| **F3** | 主题模板体系 | P1 | ⬜ 待规划 | 可切换的主题模板，支持复制到微信公众号 |

**F1 导出能力**——补齐项目当前最大的短板（没有任何内容出口）。四个动作统一收进「导出」下拉：复制 Markdown 走 Clipboard API（需为 `file://` 保留降级路径）；导出 HTML 需内联主题、highlight.js、KaTeX 三套样式；导出 PDF 优先做 `window.print()` + `@media print`（当前样式表里一条打印规则都没有），而非引入 html2pdf.js；导出 Word 先用 `application/msword` MIME 出 `.doc`，视反馈再决定是否用 `docx` 库生成真 `.docx`。

**F2 界面与交互优化**——已核实的现状问题包括：无打印样式、无 `aria-label`、编辑器字体栈缺显式兜底（`JetBrains Mono` 等多数机器未装）、Toast 分级几乎没用上、危险操作确认只覆盖了 2 处、Esc 关闭弹窗只在「水印」弹窗实现，以及缺查找替换、字号行高调节、窄屏适配。

**F3 主题模板体系**——调研了 doocs/md（MIT，3 套内置主题 + 自定义 CSS 编辑器）与 mdnice（**GPL-3.0**，20 套文章主题 + 7 套代码主题）。

> ⚠️ **License 风险**：本项目为 MIT，mdnice 为 GPL-3.0。直接搬运其主题 CSS 会因 GPL 传染性迫使本项目整体转为 GPL-3.0。建议只借鉴配色思路自行实现，或以 MIT 的 doocs/md 为蓝本。

该模块有个**前置技术约束**：微信编辑器会过滤 `<style>` 标签与 class，主题样式必须内联到元素的 `style` 属性。项目当前的复制路径是注入整个 `<style>` 块（`getThemeStyles()`），存在被剥离的风险，需先重构渲染管线再谈主题扩展。

## 二次开发

改完直接刷新浏览器即可，**没有构建步骤**。几个容易踩的点：

- **marked 版本**：见上方技术栈的版本注意，不要随手升级。
- **滚动容器**：真正的滚动容器是 `#previewWrap`（`overflow:auto` 在它身上），不是 `#previewScroll`。任何滚动监听绑错地方都会静默失效。
- **大纲跳转**：跳转期间会调用 `suppressSync(600)` 临时关闭双向同步滚动，否则两栏的程序化滚动会互相拉扯。
- **水印的两套渲染**：预览走 `buildWatermarkUrl()`（CSS 背景），复制走 `injectWatermarkNodes()`（DOM 节点），两条路径需要同步维护。
- **DOM 结构约束**：`js/app.js` 通过 `$('#id')` 取元素，改动 HTML 时请保持 id 不变，或同步修改 JS 引用。
