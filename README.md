# Markdown-Editor

一个开箱即用的在线 Markdown 编辑 / 预览工具，专注于**微信公众号排版场景**：分屏实时预览、富文本一键复制、外链转脚注、水印、模板套用。

纯静态三文件，无需安装依赖、无需构建，起个本地服务就能用。

## 特性

**编辑与渲染**

- 左右分屏实时预览，中间分隔条可拖拽调整比例
- 双向同步滚动（可关闭）
- 代码块语法高亮（highlight.js）
- 数学公式渲染（KaTeX，行内 `$...$` / 块级 `$$...$$`）
- Mermaid 图表（流程图、时序图、类图等）
- 支持 `marked` 的 GFM 语法：表格、任务列表、删除线等
- 引用块支持多段与嵌套，段间距与层次缩进按 GitHub 的做法处理
- 单行换行按 `<br>` 渲染（`breaks: true`，对齐 doocs/md）
- 底部实时统计字符数 / 词数 / 行数

**微信排版**

- 一键复制为富文本，可直接粘贴进公众号编辑器（保留代码高亮与主题样式）
- 外链转脚注：把正文中的 `http(s)` 链接变成上标序号，并在文末生成「参考文献」区块
- 水印：可自定义文字、颜色、字号、透明度、角度、间距，同步作用于预览与复制结果
- 模板：用 `{{ content }}` 占位符预置头尾结构，一键套用
- 预览模式：设备档（PC / iPad / APP）平铺在预览工具栏上、点一下就切——PC 按 Web 原貌、iPad 按平板、APP 按公众号排版，提前看到目标环境的版心与字号（只影响预览，不进产物）

**导出与留存**

- 顶栏「导出」下拉，**五个动作一站到位**：复制 Markdown 源码 / 导出 HTML / 导出 PDF / 导出 Word / 打印
- 全部通过浏览器本地下载落盘，**不经过任何服务端**
- 导出的 HTML 是**完全自包含的单文件**——主题、代码高亮、公式样式全部内联，与 CDN 脱钩，断网也能正常打开
- **「导出 PDF」与「打印」是两件事**：前者把预览渲染成图片、按 A4 切片，直接**下载一个 `.pdf` 文件**（点一下就拿到，不用在对话框里点来点去）；后者交给浏览器打印管线（矢量、文字可选中，也可在那里另存为 PDF），并带一套打印样式：自动摘掉顶栏 / 工具栏 / 编辑区 / 大纲，解除滚动容器截断，代码块与公式不被分页切断
- 导出 Word 为 `.doc`（HTML 套壳），保留基本排版，元数据面板自动降级为表格
- 文件名优先取文档元数据的 `title`，其次首个 H1，并自动清洗非法字符

**本地文件夹（只读）**

- 顶栏**「打开」**下拉里的**「文件 / 文件夹」**：一个是打开单个文件，一个是打开整个目录。收进一个菜单，顶栏按钮不再继续横向膨胀
- 打开目录后左侧抽屉列出**文件树**，点节点即切换文档——预览、大纲、字数统计、元数据面板全部自动跟随（渲染层零改动）
- **懒加载**：只枚举「已展开」的目录，并默认忽略 `node_modules` / `.git` / `dist` / `build` / `out` 等，顶层几百个文件也不卡
- **只列 Markdown 文档**（`.md` / `.markdown` / `.mdx`）：图片、配置、`.txt` 等一律不进树；**被过滤掉的文件会就地说明**（如「已过滤 3 个非 Markdown 文件」），一个不剩时补一句「（无 Markdown 文档）」，不会让人误以为文件丢了
- **目录在前、数字感知排序**（`第2章` 会排在 `第10章` 前面）
- **头部就是工作区名**：不单占一行「文件树」标题，操作（全部展开 / 全部收起 / 换文件夹 / 收起）挂在名字这一行的尾部
- **展开 / 收起**：头部有「全部展开 / 全部收起」；抽屉收起后左缘留一个主题色小把手（垂直居中），点它就把抽屉拉回来
- **编码安全**：UTF-8 / UTF-8+ BOM / UTF-16（带 BOM）正常读入；非 UTF-8（如 GBK）按 GBK 只读预览并明确提示
- 不支持该 API 的浏览器（Firefox / Safari）**只留「文件」一项**，退回原有单文档模式
- **只读**：浏览与切换文档都不改动磁盘上的文件（写回见「未来功能升级」的 F5-b）

**效率工具**

- 文档大纲：右侧悬浮面板，点击标题左（源码）右（预览）双栏联动跳转
- 全屏预览 + 页宽调节（窄 680 / 中 880 / 宽 1100 / 超宽 1400 / 铺满），全屏期间设备档锁定为进入前那一档
- 标题自动编号（H1–H3）
- 一键插入目录（TOC）
- 方格背景（便于截图对齐）
- 打开本地 `.md` / `.markdown` / `.txt` / `.mdx` 文件
- URL 链接采集：输入网址抓取正文并转为 Markdown
- 更多工具导航：内置同类在线工具与开源项目的快捷入口
- 2 套主题（GitHub / 晴空蓝），顶栏下拉即时切换，选择记入 localStorage

**文档元数据**

- 自动识别文件首部的 YAML Front Matter，在预览顶部渲染为 **Obsidian 风格的「属性」面板**（类型图标 + 键 + 值）
- 嵌套对象与数组**逐层展开**，每个叶子属性独占一行，层级用缩进与竖线标出
- `tags` / 数组值渲染为胶囊标签，布尔值渲染为 `✓` / `✗`，日期不会被时区位移
- 键前的图标按值类型自动推断：文本 / 列表 / 数字 / 复选框 / 日期 / 时间 / 标签
- 三档展示方式（属性 / 源码 / 隐藏），选择记入 localStorage
- 元数据不计入字数统计、不进入文档大纲、不参与标题自动编号，**源码不被改动**

**持久化**

- 编辑内容自动存入 localStorage，刷新不丢

## 快速开始

### 方式一：本地 HTTP 服务（推荐）

```bash
cd mdtu-editor

# Python 3
python -m http.server 20001

# 或 Node
npx serve . -l 20001
```

浏览器打开 <http://localhost:20001>。

> 端口遵循 `200xx` 约定；若 `20001` 被占用，依次顺延为 `20002`、`20003`……

### 方式二：直接双击打开

直接双击 `index.html` 以 `file://` 方式打开也可以运行。但部分浏览器对 `file://` 页面的 localStorage 有限制，可能出现内容无法保存的情况，**建议优先使用本地服务**。

### 环境要求

- 任意现代浏览器（Chrome / Edge / Firefox / Safari）
- **需要联网**：marked、highlight.js、KaTeX、Mermaid、DOMPurify、js-yaml 均通过 jsDelivr CDN 加载

## 使用说明

### 编辑与预览

左侧写 Markdown，右侧实时渲染。顶部工具栏提供 18 个语法插入按钮：

| 分组 | 按钮 |
|------|------|
| 文本 | 粗体、斜体、删除线 |
| 标题 | H1、H2、H3 |
| 插入 | 链接、图片、行内代码、代码块 |
| 列表 | 无序列表、有序列表、任务列表、引用 |
| 块级 | 分割线、表格、数学公式、Mermaid 图表 |
| 右侧 | URL 链接采集、清空内容 |

### 引用与换行

**单行换行按 `<br>` 渲染。** 解析器使用 `marked` 的 `breaks: true`，也就是源码里直接回车换行就会真的换行，不必为了换行留一个空行：

```markdown
> 第一行
> 第二行
> 第三行
```

渲染为三行。这一档与 [doocs/md](https://github.com/doocs/md)（同样基于 marked 的微信排版工具）一致；GFM 的默认行为是把这三行折成一行「第一行 第二行 第三行」，中文写作场景下很容易被当成排版 bug。

代价是：如果你习惯把英文段落**硬换行**在 80 列，渲染时就会按你的折行位置断行。需要恢复 GFM 折行行为时，把 `js/app.js` 里 `marked.setOptions({ breaks: true })` 改成 `false` 即可（全文只有这一处）。引用块与普通段落共用该语义。

**引用块（`>`）排版。** 支持嵌套与多段，并按 GitHub 的方式处理外边距：

| 写法 | 渲染 |
|------|------|
| `> 甲` | 单段引用，左侧一条竖线 |
| `> 甲` + `>` + `> 乙` | 同一条竖线内的两个段落，段间距与正文一致 |
| `> > 甲` | 嵌套引用，逐层缩进 20px 并各自带竖线 |
| `> - 甲` / `> ```js` | 列表、代码块等块级元素正常保留样式 |

有一个容易踩的坑：GitHub 官网只把引用块**首/末**子元素的外边距归零，中间的段落仍靠 `p` 自身的 `margin` 分段。早期实现写成了 `blockquote p { margin: 0 }`，导致多段引用实测段间距为 `0px`、两段直接粘成一坨——这个写法现在在 `style.css` 与 `copyToClipboard()` 的样式字段里都已被禁止，并有回归测试盯着。

### 复制到公众号

点击右上角**「复制」**按钮，渲染结果会以富文本形式写入剪贴板，直接粘贴到公众号编辑器即可，样式与代码高亮一并保留。

底层使用 `document.execCommand('copy')` 配合 Range 选区实现——这是个已废弃但兼容性最好的 API，目前是浏览器里复制富文本最稳的方案。

### 导出

点击顶栏**「导出」**（在「复制」左侧）展开菜单，五个动作：

| 动作 | 产物 | 说明 |
|------|------|------|
| 复制 Markdown | 剪贴板 | 复制编辑器里的**源码原文**（不是渲染结果）。非安全上下文下自动降级为 `execCommand` |
| 导出 HTML | `.html` | 单文件、样式全内联，断网可打开 |
| 导出 PDF | `.pdf`（**直接下载**） | 预览渲染成图片 → 按 A4 切片 → 打包 PDF。点一下就拿文件，不经过任何对话框 |
| 导出 Word | `.doc` | `application/msword` 套壳，Word / WPS 可打开 |
| 打印 | 打印对话框 | 走浏览器打印管线，矢量输出，文字可选中；打印样式自动去掉界面元素 |

文件名按「元数据 `title` → 首个 H1 → `document`」自动生成。

#### 「导出 PDF」和「打印」是两件事

这两项长得像，实际走的是两条完全不同的管线，按需要挑：

- **导出 PDF = 下载**：把预览区离屏渲染成画布，按 A4 可用高度切成若干页（切缝会自动找最近的空白行，避免把一行字拦腰截断），再逐页塞进 PDF 下载下来。**零新增运行时依赖**，库（`html2canvas` + `jsPDF`）只在第一次点这项时才从 CDN 拉。
  - 代价是**文字是图片**——PDF 里的内容不可选中、不可检索。要可检索的 PDF，请用「打印」。
  - 极长的文档会撞上浏览器的画布尺寸上限，这时会**明确拒绝并提示改用「打印」**，而不是偷偷给你一份被截断的文件。
- **打印 = 渲染后的动作**：直接调起系统打印对话框，在「目标 / 打印机」里选「另存为 PDF」即可存成**矢量、文字可选**的 PDF。页边距样式已设好（16mm）。

几个已知差异：

- **导出的 HTML 完全自包含**，与 CDN 脱钩；但正文里的图片仍是原链接（本地图片请自行处理）
- **导出 Word 不带水印**，且元数据面板会降级为两列表格（Word 不认 flex 布局）
- 导出 HTML / Word 会以 HTML 注释形式**保留 YAML 元数据原文**，便于拿到文件后二次编辑
- 打印样式**不会影响屏幕显示**（只作用于打印媒体），界面上看不到任何变化

### 预览模式（设备档）

预览工具栏左侧有一组设备档按钮，用来把「同一篇稿子在不同设备上长什么样」提前看出来。**三档全部平铺、点一下就切**（不藏在下拉里）。每档隐含「这个尺寸下最典型的阅读场景」，平台规则直接内建在档位里，不需要再单独选平台：

| 档位 | 设备视口 | 排版基调 | 代码块 |
|------|---------|---------|--------|
| **PC**（默认） | 不限宽，上限 820px | Web —— 主题原貌 | 可横向滚动 |
| **iPad** | 768px | Web + 平板适配（正文放大到 17px、行距放宽、内边距加宽） | 可横向滚动 |
| **APP** | 375px | **公众号**（正文 17px / 行高 1.75 / 字距 +0.5px） | **不支持横向滚动**，长行硬折行 |

iPad 与 APP 两档会在版心外压深一层底衬、收一个圆角，模拟一块屏幕，设备边界看得见。

**APP 档就是「手机上读公众号」的观感。** 公众号正文版心约 677px，明显宽于手机屏，所以实际版心由 375px 视口决定；正文度量则按微信的来——这也是 APP 档代码块会**硬折行**的原因：微信正文不支持横向滚动，长代码行会被折断。预览就按折行显示，把这个问题提前暴露，而不是等粘贴进公众号后台才发现。

切到哪一档，按钮自己就高亮着，正文立刻跟着变——**不弹任何提示**：浮层会挡住正文、还要停留两三秒，反而挡住你想看的东西。每档在看什么见上表。

> **只影响预览，不进产物。** 设备档类（`device-*`）是「观察工具」，复制到公众号、导出 HTML / Word 之前会被摘掉，不会被当成真实排版带进产物——它与方格背景、编辑器专用属性走同一条剥离路径。

选择记在 localStorage（`mdtu-device`），下次打开还在。

### 外链转脚注

点击顶部**「外链转脚注」**开启（按钮高亮为激活态）。

原文：

```markdown
更多信息参考 [Google](https://google.com) 和 [MDN](https://developer.mozilla.org)
```

渲染结果：

> 更多信息参考 Google<sup>[1]</sup> 和 MDN<sup>[2]</sup>
>
> ---
> **参考文献**
> [1] https://google.com
> [2] https://developer.mozilla.org

用于绕开公众号正文不支持外链跳转的限制。

### 水印

点击顶部**「水印」**按钮打开设置面板，左侧调参、右侧实时预览。

| 参数 | 范围 | 默认 |
|------|------|------|
| 水印文字 | 任意文本 | 空（附 3 个快捷预设） |
| 颜色 | 取色器 | `#999999` |
| 字号 | 10–48 px | 16 px |
| 不透明度 | 3%–60% | 12% |
| 旋转角度 | -90°–90° | -30° |
| 排列间距 | 80–360 px | 180 px |
| 复制时带上水印 | 开关 | 开 |

实现上有意做了两套渲染路径：

- **预览**：生成 SVG data URI 作为平铺背景，性能好、不污染 DOM
- **复制**：公众号编辑器会过滤 SVG data URI 背景，因此改为生成一组绝对定位的 `<span>` 节点铺在正文上，DOM 元素更容易在粘贴后存活

水印只作用于预览和复制结果，**不会改动 Markdown 源码**。

### 模板

核心是 `{{ content }}` 占位符——它代表你当前的正文。

1. 点击**「使用模板」**打开模板管理
2. 新建模板，填写名称与内容，用 `{{ content }}` 标记正文插入位置
3. 保存后选中该模板，点击**「应用模板」**

示例模板：

```markdown
# 技术周报

> 作者：XXX ｜ 发布日期：XXX

{{ content }}

---

> 关注我的公众号 👇
```

应用后，编辑器里的原有正文会被塞进 `{{ content }}` 的位置，上下自动拼接头尾。模板保存在 localStorage。

### 文档大纲

点击顶部**「大纲」**按钮，面板在右侧垂直居中悬浮。

- 自动扫描 H1–H6，按层级缩进展示
- 点击条目时，编辑器与预览区**同时**平滑滚动到对应位置
- 滚动预览区时自动高亮当前标题
- 内容编辑后实时更新
- 再次点击「大纲」或点 `×` 关闭

### 全屏与页宽

点击预览区右上角全屏图标进入全屏（`Esc` 退出）。**全屏是「安静读」的场景，进去就锁定当前档位**：设备档那一组按钮整体隐藏（不让人在全屏里来回切），正文仍按**进入时那一档**的版心渲染。

页宽控件只在 PC 档出现（`窄 680 / 中 880 / 宽 1100 / 超宽 1400 / 全屏宽`）——iPad / APP 的版心就是设备尺寸，再叠一层「页宽」只会互相打架。切换后为正中的「纸张」样式（白底 + 阴影 + 圆角）。选择会记入 localStorage，下次进入全屏自动沿用。

### 打开本地文件

点击顶部**「打开」**→**「文件」**选择本地文件，支持 `.md` / `.markdown` / `.mdx` / `.txt`，以 UTF-8 读入。若编辑器已有内容会先弹确认，避免误覆盖。打开成功后**不弹提示**——正文已经换掉了，再盖一层浮层只是碍事。

注意：这只是一个**读取**动作，页面内的编辑不会写回原文件。

### 打开文件夹（只读）

点击顶部**「打开」**→**「文件夹」**（Chromium 系浏览器才有此项）选择一个目录，左侧滑出**文件树抽屉**，点节点即切换文档：

- **目录**：点一下展开 / 收起，子目录按需读取（懒加载），不递归铺开
- **文件**：只列 Markdown 文档（`.md` / `.markdown` / `.mdx`）。图片、配置、`.txt` 等一律不进树；**被过滤掉的文件会就地说明**（如「已过滤 3 个非 Markdown 文件」），某个目录里一个 MD 都没有时补一句「（无 Markdown 文档）」
- **当前文档**会在树上高亮；抽屉宽度可拖动右缘调整（记入 localStorage）
- **抽屉头部就是工作区名**，不单占一行「文件树」标题；操作（全部展开 / 全部收起 / 换文件夹 / 收起）都挂在名字这一行的尾部，字体全树统一 13px
- **显示 / 隐藏**：顶栏菜单里那一项本身就是开关（展开时带激活态），抽屉头部的 `×` 收起它；**收起后左缘会留一个主题色的小把手**（垂直居中、圆角），点一下就把抽屉拉回来
- **全部展开 / 全部收起**：头部两个按钮。展开是**逐个读盘**的，几千文件的目录会拖死 UI，所以设了 400 个目录的上限，到顶停手并如实告知
- 抽屉默认收起、与其他浮层一样**不进打印 / 导出产物**，单篇写作时完全不打扰

切换文档本质就是「换 `editor.value` + 重渲染」，因此**主题、大纲、字数统计、元数据面板、水印、外链转脚注全部自动跟随**。

注意两点：

1. 本期（F5-a）是**只读**——浏览与切换都不写磁盘，编辑结果仍只存在 localStorage 里。
2. **非 UTF-8 文件**（如 GBK 编码）会按 GBK 解码后**只读预览**并明确提示——这是唯一在打开时会弹提示的情况，因为它不是原文件字节的忠实还原。把它写回磁盘是 F5-b 之后才需要考虑的事。

### 文档元数据（Front Matter）

很多编辑器与静态站点生成器（Typora / Obsidian / Hexo / Hugo / Jekyll）会在 `.md` 文件首部写一段 YAML Front Matter：

```markdown
---
title: 示例文章标题
author: 张三
date: 2026-09-20
tags: [markdown, wechat]
draft: false
---

# 正文从这里开始
```

打开这类文件时，元数据块会被**自动剥离**，并在预览顶部渲染为一块 Obsidian 风格的**「属性」面板**——圆角卡片 + 每行「类型图标 + 键 + 值」，键列定宽，所以各行的值左边缘对齐：

| 键 | 类型图标 | 值 |
|----|----------|-----|
| `title` | 文本 | 示例文章标题 |
| `author` | 文本 | 张三 |
| `date` | 日历 | `2026-09-20` |
| `tags` | 标签 | `markdown` `wechat`（胶囊标签） |
| `draft` | 复选框 | ✗ |

值的呈现方式：

| YAML 值 | 渲染 |
|---------|------|
| 字符串 / 数字 | 原样输出（HTML 已转义） |
| 布尔 | `✓` / `✗` |
| 标量数组 | 胶囊标签（`tags` / `keywords` / `categories` 一律如此，单值写法也按标签渲染） |
| 日期 | 归一化为 `YYYY-MM-DD`，不做时区转换 |
| 对象 / 含对象的数组 | **逐层展开**，每个叶子属性独占一行 |

**嵌套结构会递归展开**，不会被挤成一行。分组键渲染为「容器行」（右侧显示直接子项数），子属性按层级缩进、左侧用竖线标出层次；数组元素用下标 `[0]` `[1]` 作行标。例如：

```markdown
---
doc:
  title: 文档标题
  author: 张三
assets:
  cover: ./img/cover.png
  authors:
    - name: Ann
      pages: 320
---
```

预览中会摊开成 5 行属性——顶层虽然只有 2 个键，但标题行与状态栏都按**叶子属性总数**计数：

```
属性 5 项
▾ doc                       2 项
│   T title       文档标题
│   T author      张三
▾ assets                    3 项
    T cover       ./img/cover.png
    ≡ authors     1 项
        ▾ [0]     2 项
            T name    Ann
            # pages   320
```

- 标量数组（如 `tags: [a, b]`）不会展开，仍在一行内渲染为胶囊标签
- 缩进与层级竖线全部内联，复制到公众号后层级关系不会丢

**三档展示方式**：预览区工具栏左侧会出现「元数据」下拉（仅在检测到元数据时露出）：

| 档位 | 行为 |
|------|------|
| 属性（默认） | 渲染为「属性」面板 |
| 源码 | 渲染为 YAML 代码块，保留原文 |
| 隐藏 | 预览中完全不出现 |

> 复制到公众号时，面板里的「属性 · n 项」标题行会被自动摘掉（属于应用 UI，不属于文章内容）；卡片与标签样式全部内联，会随富文本一起带过去。

几个边界行为：

- **源码零改动**——元数据只影响预览与复制结果，编辑器里的原文一字不动
- **不计入统计**——字符 / 词 / 行数只算正文，状态栏会额外标注「元数据 N 项（未计入）」
- **不污染大纲与编号**——元数据不进入文档大纲，也不参与标题自动编号
- **容错**——闭合 `---` 缺失、或 YAML 语法有误时不会吞掉正文：块会被剥离并以「源码」形态回显 + 提示
- **不会被误判**——正文恰好以 `---` 分割线开头的文档不会被当成元数据

## 已知限制

1. **导出 PDF / Word 不是原生格式**——**「导出 PDF」是直接下载**，但它把预览渲染成了图片再装箱，所以 PDF 里的**文字不可选中、不可检索**；要可检索的矢量 PDF，请用**「打印」**并在打印对话框里选「另存为 PDF」。导出 Word 是 `.doc` HTML 套壳而非真 `.docx`，部分客户端会弹格式兼容提示，且不带水印。**导出 HTML 是完全自包含的单文件**（样式全内联、断网可打开）。另外，正文本身仍只存在 localStorage 里，`Ctrl+S` 也不等于存盘。
2. **「打开 → 文件 / 文件夹」都是只读的**——读取文件 / 浏览文件夹后，页面内的编辑不会写回磁盘。文件夹模式（F5-a）已能打开整个目录并在文件树里切换文档，但**写回磁盘是 F5-b**，尚未实现（见下方「未来功能升级」的 F5）。
3. **URL 采集依赖公共代理**——走 `api.allorigins.win` 做 CORS 转发，该服务不稳定时此功能会失败，且部分站点会因反爬而抓取不全。
4. **离线不可用**——依赖库全部走 CDN，无网络时渲染链路会瘫痪。
5. **水印不保证在公众号生效**——已用 DOM 节点方案提高存活率，但微信仍可能二次过滤样式，粘贴后请确认。
6. **主题入口曾长期隐藏**——4 套主题此前被 `display:none` 隐藏、锁定 GitHub；2026-10-13 起放开，并精简为 **2 套（GitHub / 晴空蓝）**。详见 FAQ。
7. **无移动端适配**——分屏布局面向桌面端设计。

## FAQ

**内容会丢吗？**

换浏览器、清缓存、使用无痕模式都会导致 localStorage 数据丢失。`Ctrl+S` 也只是写 localStorage，不等于存盘。重要内容请手动复制出来备份。

**主题下拉框在哪？**

在顶栏中段、「大纲」左侧。目前有 **2 套：GitHub / 晴空蓝**。主题下拉此前一直被 `style="display:none;"` 隐藏、锁定 GitHub；**2026-10-13 起已放开**，同日把原「山吹 / 山月 / 凝夜紫」精简为 GitHub + 晴空蓝（「山吹」更名「晴空蓝」，另两套下线）。选中项写入 `localStorage['mdtu-theme']`；老存档里的旧主题名会自动收敛到新主题，不会出现空选（见 [ROADMAP 的 F3](./ROADMAP.md#f3--主题模板体系)）。

要重新隐藏，给 `index.html` 里 `#themeSelect` 所在的 `.toolbar-group` 与其后紧跟的 `.toolbar-divider` 各加回 `style="display:none;"` 即可。

**预览模式（设备档）是什么？**

预览工具栏左侧的一组设备档按钮：**PC / iPad / APP**，点一下就切，默认 **PC**。三档各自带着「这个尺寸下最典型的阅读场景」——PC 按 Web 原貌（版心 820px）、iPad 按平板适配（768px / 正文 17px）、APP 按**公众号排版**（375px 视口 / 正文 17px / 字距 +0.5px / 长代码行硬折行）。选择记入 `mdtu-device`。**只影响预览**，不会进入复制 / 导出的产物。逐项说明见[使用说明 · 预览模式](#预览模式设备档)。

**`index.html` 里的 `data-page-node-id` 是什么？**

那是 **WorkBuddy 资料库「页面」平台**给页面里每个节点打的 id（内部叫 `pnid`），用途只有两个：**节点级评论**的锚点、**「划词让 AI 改」**时定位改哪个节点。这份 HTML 被托管成资料库页面后就会带上，**与本项目的代码无关**（`js/app.js` / `css/style.css` 全文零引用它）。

它实测有 **312 个属性、13.4 KB，占 index.html 的 35%**，会让整份文件的 git diff 被淹没。**2026-10-13 已确认项目里没有任何代码读它，整批清除**。所以现在 `index.html` 是干净的；`stripEditorOnlyAttrs()` 那段剥离逻辑**保留着做防御**——万一这份文件又被托管回资料库，属性会重新出现，不拦就会跟着克隆漏进复制 / 导出的产物（ex-test 有一条「手动注入 pnid → 导出应剥掉」的用例锁着）。代价是：**那份资料库页面上的历史评论会失锚**。

**图标（标签页 / 桌面快捷方式）在哪改？**

图标就是仓库根目录那份 **`Markdown.ico`**（既有的成品，蓝色底，六帧 16/32/48/64/128/256）。**页头左上角、浏览器标签页 / 窗口、桌面快捷方式三处共用同一个文件**——页头用的是 `<img class="logo-icon" src="Markdown.ico">`，标签页用 `<link rel="icon" href="Markdown.ico">`。项目**只保留这一个图标文件**——不另产 `favicon.ico`，也没有配套的 `apple-touch-icon.png`，避免几份图标各说各话。要换图标，直接替换这个文件即可（三处同步生效，不需要重新生成）。

桌面入口：用 Edge/Chrome 的「…→ 应用/更多工具 → 创建快捷方式」建；已有手动创建的 `.lnk`，可在「属性 → 更改图标」里指到 `Markdown.ico`。（本地 `file://` 打开的页面不支持「安装为应用」，那一项需要走本地服务。）

**改了默认文档为什么没生效？**

默认内容只在 localStorage 中没有 `mdtu-content` 时加载。老用户需要在控制台执行：

```js
localStorage.removeItem('mdtu-content')
```

再刷新页面。

**渲染卡住了 / 一片空白？**

先确认能访问 `cdn.jsdelivr.net`，依赖加载失败会导致整条渲染链路不可用。

**F6 预览模式（设备档）**——✅ **已完成**。预览工具栏左侧是一组**平铺的档位按钮**（点一下就切，不藏在下拉里）：**PC / iPad / APP**，默认 PC。三档各自隐含「这个尺寸下最典型的阅读场景」，平台规则直接内建在档位里，不需要再单独选平台——**PC** 按 Web 原貌（820px 上限）、**iPad** 按平板适配（768px，正文放大到 17px、行距放宽、内边距加宽）、**APP** 按**公众号排版**（375px 视口 / 正文 17px / 行高 1.75 / 字距 +0.5px / 长代码行硬折行）。**只影响预览，不进入复制 / 导出产物**。用法见上方「使用说明 · 预览模式」，实测数据见 [ROADMAP 的 F6 章节](./ROADMAP.md#f6--预览模式设备档)。**零新增依赖**。

**F5 文件夹模式**——🟦 **部分完成（F5-a 已落地）**。把工具从「单篇排版器」扩展为「本地 Markdown 工作区」：打开整个目录、在文件树里切换文档、把编辑结果写回磁盘上的原文件。走浏览器原生 **File System Access API**，**零新增依赖、零构建步骤**。可行性已实测确认：`file://` 属于安全上下文，该 API 在「直接双击打开」下同样可用，**现有两种打开方式都不必废弃**（三组对照实验见 [F5-FOLDER-MODE.md](./F5-FOLDER-MODE.md#3-能力实测可行性判定)）。

## 二次开发

改完直接刷新浏览器即可，**没有构建步骤**。几个容易踩的点：

- **marked 版本**：见上方技术栈的版本注意，不要随手升级。
- **滚动容器**：真正的滚动容器是 `#previewWrap`（`overflow:auto` 在它身上），不是 `#previewScroll`。任何滚动监听绑错地方都会静默失效。
- **大纲跳转**：跳转期间会调用 `suppressSync(600)` 临时关闭双向同步滚动，否则两栏的程序化滚动会互相拉扯。
- **水印的两套渲染**：预览走 `buildWatermarkUrl()`（CSS 背景），复制走 `injectWatermarkNodes()`（DOM 节点），两条路径需要同步维护。
- **元数据的剥离时机**：`splitFrontMatter()` 必须在 `marked.parse()` **之前**调用。marked v4 不认识 front matter，直接把原文喂进去会被解析成 `<hr>` + 一个吞掉全部元数据的假 `<h2>`。
- **js-yaml 的 schema**：解析元数据时必须显式传 `CORE_SCHEMA`。默认 schema（YAML 1.1）会把 `date: 2026-09-20` 解析成 `Date` 对象，序列化后是 `2026-09-20T00:00:00.000Z`，东八区会显示成前一天。
- **元数据块用内联样式**：`buildFrontMatterBlock()` 按主题直接输出内联 style，不走 `getThemeStyles()`——因此换主题后必须重渲染才能变色（`applyTheme()` 里已经带上 `renderMarkdown()`）。
- **DOM 结构约束**：`js/app.js` 通过 `$('#id')` 取元素，改动 HTML 时请保持 id 不变，或同步修改 JS 引用。
- **导出的样式内联**：导出 HTML 时会把主题样式与两张 CDN 样式表（hljs / KaTeX）的**文本**拼进文件，内联前必须先把 CSS 里的 `url()` 绝对化——KaTeX 的 `@font-face` 写的是相对路径，不处理会导致导出文件里公式字体全部 404。相关函数集中在 `js/app.js` 的 `// ===== Export (F1) =====` 段。
- **打印样式只影响打印**：`@media print` 里的规则改坏了不会在屏幕上显现，改完要用浏览器的「打印预览」或 `--print-to-pdf` 验证。
- **块级公式的换行坑**：`breaks: true` 会把段落内换行变成 `<br>`，多行写的 `$$…$$` 因此被拆成多个文本节点，KaTeX 的 auto-render 配不上定界符、整个公式不渲染。`renderMath()` 开头的 `unfoldDisplayMath()` 负责把它们合回去，动这块代码时别漏。
- **预览容器的 class 只有一个出口**：主题、方格背景、设备档三维由 `syncPreviewClass()` 统一拼装，全文只允许一处写 `preview.className = [`；别处整串覆盖会把其余维度静默冲掉。`device-*` 是观察工具，进产物前必须在两条克隆路径上剥掉（`stripPreviewModeClasses()`）。
- **设备档选择器要写两级**：`.markdown-body.device-app` 而非 `.device-app`——主题段 `.theme-*` 也声明 `font-size`，且排在设备档之后，单级选择器会被顶掉。
